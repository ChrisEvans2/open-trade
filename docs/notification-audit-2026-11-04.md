# 预测通知规则与发送边界

公开技术说明：预测通道只发父Agent摘要和错误告警；不包含个人部署状态、实际送达回执或历史预测记录。

## 现在什么消息发到哪里

| 消息 | 接收通道 | 触发与次数 |
| --- | --- | --- |
| 程序启动、系统/账户与执行状态 | 主控 TG | 每次成功启动一条；原有账户/执行通知保留 |
| 父综合预测结果，含 HOLD | 预测 TG | 每次发布一条摘要，包含结构、方向概率、父意图、有效期和简要依据；不逐条推送子周期成功消息 |
| 分析报错 | 预测 TG | 每个错误组首次失败和停止重试时告警；恢复后只发正常父摘要 |
| 子周期结果、目标达成、到期、失效、歧义及分析恢复成功 | 不推送 | 保存业务状态与评分，按规则继续分析 |
| 主控主动申请的解释/复盘结果 | 主控 TG | 请求完成后回复原主控通道 |

系统健康异常/恢复的doctor通知走主控，是否启用定时检查由独立部署配置决定。预测状态须经程序确认；行情缺失可能推迟确认。通知不会重置账户熔断，预测到期本身不触发平仓。

## 发送与事实保护

系统使用主控目标和Profile；配置独立预测目标后，预测通知使用预测Profile。复用原outbox/HermesSender，不另建网关。默认发送预算30秒，配置范围10至60秒；每批最多并发4条，发送前检查领取归属、租约与fence，外部发送不放进数据库事务。

发送结果未知时保留UNKNOWN并停止自动重发；确认未发送的错误才按既有策略有界重试。通知入队与对应业务事实在同一事务提交。旧待发成功状态可停止推送，历史正文、目标及SENT/UNKNOWN不重写。

## 验证边界

单元与真实隔离PostgreSQL覆盖路由、父动作摘要、状态静默、错误告警、事务回滚、旧待发停发与发送结果未知处理。当前发布数量见changelog。受控测试不等于真实TG送达验收，不证明模型、采集或账户状态健康。
