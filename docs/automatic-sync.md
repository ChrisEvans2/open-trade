# 框架自动同步

维护环境使用独立的后台同步器，每分钟检查开发工作区中允许公开的代码。文件稳定两分钟后，生成候选树、验证，再在本仓库独立提交和推送。该维护任务不是交易runtime，不会启动交易或接管账户。

## 同步范围

- 已审核的项目文件：runtime、core/quant、迁移、插件、提示词、测试、完整README/需求/技术文档、通用工具及退役源码。
- 上述代码目录中新增的非忽略Python文件，以及结构提示词目录中的Markdown文件。
- 已审核的原项目README/技术文档也按三方合并同步，保留公开脱敏；本仓库专用说明、示例配置、忽略规则及通用paper服务模板保留公开适配。
- 不公开个人身份/知识库链接、原始账户/预测/交易/复盘记录、Profile、.env、备份、日志、状态或私人提交历史。含此类内容的历史文档仅保留已审核脱敏版本。新建的任意文档不会未经审核自动纳入。

已脱敏文件按“上次源文件、上次公开文件、本次源文件”做三方合并。正常框架改进可保留公开适配；涉及相同位置的冲突会阻断，不自动恢复私人配置。公开工作树、暂存区、分支或远端有独立变化也会阻断，避免覆盖维护者工作。

## 每次发布检查

1. 检查路径、文件类型、已知个人标识、凭据字面量及密钥扫描；不输出敏感匹配值。
2. 在临时候选工作区创建独立依赖环境，运行共享核心、runtime单元、固定Hermes契约、runtime静态检查，以及隔离真实PostgreSQL定向集成；涉及改动的集成测试追加运行。
3. 生成changelog，再对最终树扫描；确认源文件和公开工作区在验证期间没有变化。
4. 只继承本仓库公开历史，生成独立公开提交并推送main。不合并私人分支，不force push。

推送失败保留已成功生成的公开提交，下轮先重试该提交，不重新生成。隐私、合并或测试失败保留本地状态及日志，同一文件快照退避15分钟；源内容更新后重新等待稳定并检查。正常同步不需要手动执行命令，异常需要先修复其原因，工具不会以跳过检查来继续。

测试环境不继承交易所、业务数据库、模型或TG凭据；PG实例与业务数据库隔离。扫描依据固定规则和已知标识，不能保证识别所有未知商业信息，所以私人资料应始终留在白名单之外。

这份说明记录维护流程；同步器及其源/目标配置保存在维护环境，不属于公共交易运行依赖。

扩大范围时使用精确审核清单，绑定源文件内容、公开父版本及完整候选树；过期或被篡改的审核拒绝发布。退役源码只作参考，不安装、不部署，不恢复第二交易入口。
