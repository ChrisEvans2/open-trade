# CVD采集断点与历史回补修复

公开技术说明：保留实现、默认值与验证边界，不记录个人部署进度或实际数据覆盖。

## 模块与行为变化

| 模块 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 逐笔采集 | 一个分钟中途超时，下次重新翻页 | 每页验证后，把该页与下一次分页位置在同一事务保存；重启后接着抓 |
| 工作调度 | 新数据、历史回补及两个币种争抢整轮预算 | 增量和历史分队列、币种与队列轮转；一个任务每次最多10页或8秒，再给其他任务机会 |
| 重试 | 时间/请求预算耗尽被记成失败、指数退避 | 调度预算耗尽只暂停，不增加失败次数，不发布新的 MISSING 事实；真正网络错误和限流保留断点、退避重试 |
| 历史抽查 | 暂停的抽查可能被不断推到队尾 | 优先恢复未完成的抽查；每第三轮优先安排到期抽查，其余轮次优先增量/回补 |
| 持久化 | 原始缓存24小时过期可能不适合承担恢复职责 | 独立保存进行中的分页；不受24小时原始缓存清理影响；完成或异常需重新构建时清理，超出回补范围也可清理 |
| 可观测性 | running/循环成功不代表数据有效推进 | last_progress 随成功保存页或完成分钟更新；每轮区分有效页数、完成、暂停和失败；覆盖状态按实际收盘窗口统计 |

完整分钟仍要验证合约、单位、分页完整性、重复成交、买卖方向复算，以及与同一分钟 K 线总量一致。
满足全部条件才发布 OK。成交量一致不能证明交易所原始方向永远正确，原有风险说明继续适用。
没有改成15分钟聚合，没有用 K 线方向猜主动买卖，也没有回退到已知有问题的 Rubik 主动成交统计。

## 时间与资源策略

- 保留每轮40秒、300次逻辑请求和每轮最多12个任务处理机会。HTTP内部重试会产生额外物理尝试，
  每次尝试仍经过原有共享限速门和同一绝对截止时间。
- 每个任务默认10页/8秒网络时间片，数据库提交等处理开销另计；之前的 `max_pages_per_minute=300` 保留兼容，后台把它作为每次处理的
  额外上限，不再要求整个分钟只能在一次300页循环内完成。繁忙分钟可以跨多轮完成。
- 有有效进展时，下一轮等待0.25秒；空闲或无有效进展时仍等待15秒。不是每0.25秒无条件请求API。
- 继续使用同一 OKX 客户端的0.12秒请求间隔与限流等待；新增识别HTTP429和业务码50011。
  此门覆盖当前runtime共享客户端，不承诺限制同一IP上其他进程的独立请求。
- 近3个可采集分钟作为增量队列，其余为历史队列；历史按最新1h/4h/6h/12h计算窗口优先扩展，
  同窗口优先恢复断点和到期错误。两个币种与两类队列的首位分别轮转，防止紧预算长期只处理同一组合。
- 旧版本留下的 `MARKET_DEADLINE` / `TRADE_CYCLE_BUDGET` 等预算错误调度项重新置为待处理，
  清零这类旧失败次数；真正的网络/限流错误仍遵守既有退避。旧错误观察事实不修改。
- 默认初始化11天、回补范围30天、原始明细24小时不变。未完成分页独立留存，并非无限保留所有原始成交。

以上10页、8秒、0.25秒、60秒覆盖刷新与轮转方式是本次实现选择，不是交易所要求或用户指定值。
它们用于限制单任务占用、缩短无效等待；线上请求延迟和有效吞吐仍需部署后观察，不承诺固定补齐时间。

## 恢复与事实边界

新增0012迁移只增加 `trade_minute_checkpoints` 和 `trade_minute_pages` 两个可重建数据表；
旧0011迁移不变。每页与游标同事务提交，事务内校验runtime实例锁和代次；外部API请求在事务外。
如果页提交失败，游标不会提前前进；如果末页已提交但分钟尚未发布，重启可直接完成校验与发布。

完整分钟事实写入、工作项完成和断点清理在同一事务。可删除权限仅扩展到这两个可丢弃表；
分钟事实、K线、预测输入等仍保留原有追加和防删除保护。后续修订只影响在其可用时间之后冻结的新预测。

对于预算暂停，不生成新的缺失行情版本。正在复查的旧OK分钟在暂停或暂时网络错误时保留；
实际数据异常仍按原有方式追加质量修订，不能因恢复功能放松校验。

## 覆盖状态与验收

采集器健康状态新增 `coverage`，带 `as_of` 刷新时点；距离上次刷新满60秒后，在下一轮结束时重新读取。
复用正式预测使用的 `trade_windows` 查询，分别使用各周期自己的最后收盘边界，而不是累计历史总数。
每币每周期报告窗口起止、所需分钟、已校验分钟、缺失分钟、是否完整，以及不完整的周期区间；
另列最近10个错误工作项及重试时间。状态缓存可能滞后60秒再加一轮处理耗时，正式预测冻结仍直接读取数据库。

| 周期 | 回看20根所需有效分钟 |
| --- | ---: |
| 1h | 1200 |
| 4h | 4800 |
| 6h | 7200 |
| 12h | 14400 |

12h需要完整10天，保存格式与公式不变。补齐历史的原始请求量客观存在；此次消除重复抓取和调度饥饿，
不把首次长窗口初始化变成即时完成。

## 验证范围与限制

相关测试覆盖44页跨轮与重启恢复、持续到达与回补并行推进、重复去重、冲突页拒写、25小时后断点保留、限流恢复、失效owner拒写、末页恢复、事务回滚、暂停抽查恢复、0011升级0012、最小角色权限及完整12h窗口缺一分钟的质量变化。测试入口见[断点PG测试](../trading-agent/tests/integration/test_trade_checkpoints.py)、[分钟聚合](../trading-agent/tests/integration/test_trade_minutes.py)、[独立检查](../trading-agent/tests/integration/test_trade_checkpoint_pg_review.py)。

模拟时钟与固定响应验证调度性质，不代表真实网络延迟、接口吞吐或10天历史已补齐。实际发布测试数量见changelog；长期源数据完整性与买卖方向正确性仍需独立抽查。

## 迁移与回滚要求

升级需要备份、停止唯一旧runtime、执行0012迁移、授予新增工作表的最小权限，并核验部署锁。旧代码若仅接受0011，不能直接切回；须准备前向兼容版本。正式行情、预测、评分和交易事实保留，禁止删除事实或降低质量校验来恢复运行。
