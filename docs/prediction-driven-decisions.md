# 技术决策与必要配套

逐项对应[实现说明](prediction-driven-implementation.md)和[需求对照](prediction-driven-requirements.md)。以下为用户离开电脑后自主确定的实现细节，不代表已学习结论。

| 决策 | 原因及影响 |
|---|---|
| 单runtime、本地包依赖共享交易核心 | 2026-10-22 提取为 trading-core，复用风控/会计/退出计算；不再安装旧应用包 |
| 新0009迁移、报告schema3/API v2 | 保留旧小时分类历史原义；旧事实不重写 |
| PG为事实，SQLite仅索引 | 跨库失败不能损坏知识版本；PG提交后异步索引可重试 |
| 预测30×4=120根、计算与复盘各80×4=320根（每币种） | 窗口为用户确认要求；30根是计算历史末尾子集。原实现遗漏了复盘原始行情，本次补齐，不改变预测视图 |
| 复盘窗口取采集开始时锚点，另记冻结时间 | 本轮自主实现细节：事务外并发收集、事务内验证/冻结；缺一周期即拒绝，已冻结重试不刷新。标记REVIEW_ONLY，与案例事前证据及评分分离，不按每个历史案例再复制320根 |
| 左右2根确认极值、最近60根拟合候选、ATR14、0.25ATR | 因果地识别形态；多个候选并存，拒绝以名称自动入场 |
| 条件使用闭合分钟、确认1～5分钟 | 每分钟可重放验证；不假定分钟内先后顺序 |
| 观察窗只使用发布后/截止前完整分钟 | 避免发布前数据泄漏及过期后价格提高命中率；非逐笔验证 |
| 独立验证资格与历史观察窗口 | 失效后不能再用于决策，但方向概率仍按原窗口评分 |
| 持仓另有结构验证游标与失效记忆 | 预测到期后继续监测；补齐缺口后能发现中途失效，不只检查最新分钟 |
| 父发布前核验全部子引用及持仓版本 | 防止异步更新产生过时决策；排队合并仅用于未冻结的任务 |
| 开仓核验父子分钟验证进度 | 防止分钟游标已更新、验证事实尚未提交的竞态 |
| 决策上下文hash排除纯监控游标 | 常规验证推进不会无理由使正在综合的任务过期；持仓身份/结构失效仍会影响版本 |
| 初始期限4根、父1h尺度 | 明确初始值而非“学到”的期限；2/3/4/6/8/12候选固定 |
| 配对评分等待成本每根0.01 | 长期限需要抵消等待成本；40回放/20影子/20复查及0.02阈值均可查版本 |
| 学习限每组最近200份独立周期预测 | 限制单次工作量；父/子1h共用相同结构阶段规则，避免重复计样本 |
| 知识初始4项UNVERIFIED | 有操作指导，无虚构成功率和案例 |
| 中文双字+英文数字词的FTS5 | 无外部向量服务；能按结构/阶段召回，不能宣称语义理解或向量相似 |
| PG回退最多500个当前版本，正文6000/12000字符分页 | 索引故障仍可解释检索，限制输入和资源消耗；回退事实冻结 |
| 复盘90天/200案例、每币种每日一次 | 学习预测经验，与旧策略代码迭代分离；模型不能直接改交易策略文件 |
| RANGE要求已验证箱体及正向中点空间 | 原区间止损/中点止盈需要有效参数；不新增概率阈值 |
| 风险参数继续读取旧risk/strategy/runtime配置 | 不提升用户现有风险上限；新入口绕过方向策略/Advisor，保留社媒风险减仓/阻断与失败政策 |
| 同账户串行处理未决订单 | 用保守占用避免跨币种同时按同一权益重复定仓；未知结果可能阻止后续提交 |
| 稳定客户端ID、先持久化SENDING | 崩溃后先查；不能确认“从未发送”的情况不会自动重发 |
| 整仓结束才累计连续亏损，费用修订进入原持仓盈亏 | 部分平仓撤单不算独立交易，避免重复记亏；交易所最终退出可扣除已入账部分 |
| 账户硬风控持久暂停，operator恢复 | 重启/另一币种不能绕开账户级限制；沿用已有resume权限和审计，不新增模型解除工具 |
| 累计成交增量入账、持仓ID+revision绑定 | 重复回报不重复下单或记账；旧平仓不能作用于新仓位 |
| 结束/平仓要求时撤销未成交开仓余量 | 避免结束的预测继续增加仓位；已经成交部分不因到期被强制平仓 |
| 固定保护随开仓附带、软件继续原退出算法 | 减少开仓成功后再挂保护单之间的空档；附带价以请求价格计算，实际成交价的软件退出使用原公式 |
| 交易所自主退出要求唯一历史证据 | 不根据“持仓查不到”就伪造盈亏；身份/数量不一致先核对 |
| 默认执行关闭、不补发DISABLED意图 | 开发验证不改变线上交易；以后启用也不执行历史过期决定 |
| engine切换时有持仓/未决订单则拒绝切换 | 原结构和原执行账本不能被新版本无声遗弃；线上切换先由旧版本处理完 |
| 保留旧历史模块，移除活跃工具 | 用户要求删除旧迭代记忆用途，同时保留历史证据可追溯 |
| injected clock写入attempt.started_at | 修正真实PG测试中数据库实时时钟与可控测试时钟混用；生产仍使用同一DB时钟 |
| 新增CLI/bridge查询入口 | 新预测契约能够查看；旧历史接口不被改成新含义 |
| 结构JSON Schema纳入沙箱输入白名单 | 正式输入能过桥接校验，同时继续拒绝任意宿主文件/符号链接；结构任务不开放外网 |
| 部署锁/runtime共用engine hash，复盘恢复查原提交 | 防止部署标识不一致与已提交复盘被重放；只影响必要恢复流程 |
| 本地PG端口58917、基线hash文件 | 避免占用已有58916进程；保留其他对话的未提交改动 |

配置、未知结果、引擎切换等边界还需按[验证文档](prediction-driven-validation.md)进行在线验收。代码和测试不能证明预测能盈利。
