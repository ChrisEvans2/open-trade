## 各模块改了什么

| 模块 | 原来的问题 | 现在的行为 |
| --- | --- | --- |
| 外部统计采集 | 三种统计的时间口径未配置，程序直接跳过请求 | 开启主动买卖成交、历史 OI、多空账户比请求；只抓当前子预测需要的周期，排除尚未完成区间 |
| 数据质量核对 | 缺数原因较笼统，时间覆盖齐全就可能被认为数据完整 | 区分未配置、API 空响应、未完成区间、字段无效、请求超时；逐根核对主动成交总量与 K 线总量，不一致时保留数值并标部分覆盖 |
| 市场宽度 | 市场篮子为空，采集直接返回空 | 计算五币篮子中，高于各自 20 根均线的有效成员占比；五个有效为完整，四个有效为部分覆盖，少于四个不输出数值 |
| 资金费率 | 长周期用最后收盘时间过滤，当前费率被排除 | 当前预计费率作为决策时的可选背景，保留真实发布时间；另提供最近已结算费率序列、正负次数、均值和变化供长周期分析 |
| ETH–BTC 相对关系 | ETH 也被错误标成“BTC 对自身不适用” | 单独获取同周期、同边界的 BTC 已收盘数据，计算相关性、beta、相对强弱；缺基准时明确缺失，收益方差退化时不输出无意义数值 |
| 强平采样 | 只保留配置主标的，预测没有调用窗口聚合 | 同一公开连接保留 BTC、ETH 两币采样；分别按预测周期聚合金额，随预测输入冻结；金额、事件、连接缺口和来源均保留 |
| 模型证据规则 | 相对关系没有专门强弱限制 | 三项 ETH–BTC 指标逐项标为 WEAK，子预测、父综合和复盘均不得将其作为强证据，或累计成三份独立证据 |

子预测原有行情视图仍为 **30 根已收盘＋1 根当前未收盘快照**；后台原有指标计算仍用 80 根已收盘，临时指标仍用 80＋1。BTC 基准独立保存 80 根版本，相关计算使用其中 21 个收盘价产生 20 个收益；模型默认只收到基准状态和相对指标，不额外塞入一组 BTC K 线。父 Agent 继续只综合有效子报告，必要时读子报告原冻结证据，没有恢复父自身行情采集。

## 指标表示什么，怎样使用

- **CVD**：最近 20 个已完成区间的主动买量减主动卖量，单位为币的数量。这是窗口成交差额，不是从交易所成立以来累计的 CVD。主动买卖比则是同一窗口买量除以卖量。卖量为零时比值无定义，不用无穷大替代。
- **OI 变化**：相邻两个已完成统计区间的持仓合约数变化比例。增加只说明未平仓合约增加，不能仅凭它判断多方或空方胜出。这里采用交易所区间末值，不把它称为精确到最后一笔的收盘瞬时快照。
- **多空账户比**：当前合约持多与持空账户数量之比；不是多空资金金额比例。
- **市场宽度**：例如五币中四币高于自身 SMA20，结果为 80%。每个成员等权，只反映这个固定篮子；BTC、ETH 已在篮子中，它不是完全独立于目标币的额外证据。
- **资金费率**：当前预计费率用于描述眼下付费方向和拥挤情况；历史结算序列用于观察持续性和变化。费率不是必要的方向信号，正费率不能直接翻译成看涨或看跌。原有 funding_zscore 继续以最新合格已结算费率相对前 30 次结算衡量异常程度：1h 截至决策时，长周期截至最近收盘时。
- **ETH–BTC 相关性**：20 个同步收益的同向程度；**beta** 是 ETH 收益对 BTC 收益的线性敏感度；**相对强弱**是 `(ETH 期末/期初)÷(BTC 期末/期初)−1`。三项均只作弱证据，不能单独确认结构、突破、方向或触发交易；相关性不证明因果，也不保证之后继续联动。
- **强平不平衡**：使用样本中空头被平金额与多头被平金额的差，除以二者总额。金额依据已验证合约面值和破产价格计算，是公开样本金额口径，不能当作全市场实际成交损失。

资金费率历史摘要读取最多最近 9 个独立结算事件，展示后 8 次费率及相邻记录间隔。间隔不一致时可能是结算频率变化，也可能缺事件，因此标部分覆盖，暂停输出可比均值/变化摘要。间隔相等也不等于已证明历史无缺口。没有把记录间隔当作交易所真实结算周期，没有擅自换算成每 8 小时费率。

## 仍不能完整获得的数据，以及替代方式

| 数据或限制 | 原因判断 | 本轮处理与可用替代 |
| --- | --- | --- |
| 全量强平、采集前的历史强平 | OKX 公开 WebSocket 明确只提供近期采样，不代表全量；程序也无法补回未曾采集的事件 | 有样本则输出部分覆盖；无样本、断线或元数据不足明确记录。结合价格、OI、主动成交观察去杠杆可能，但不能据此造出强平金额或断言强平已经发生 |
| 过去任意时刻“当时预计的资金费率” | 当前费率 API 只给当前发布状态；历史结算 API 不是任意时刻的预计费率快照档案 | 以后将实际读到的快照追加保存；历史分析优先用当时已有的冻结快照和已结算记录，不以今天读到的值回填过去 |
| 部分区间的完整主动买卖分配 | 本轮实测发现部分历史 taker 统计总量低于同区间 K 线总量；交易所内部原因尚未确认 | CVD/买卖比保留 API 统计结果并降级为部分覆盖，不把差额擅自分配给买方或卖方。可辅助查看已有收益、波动、量能和 OI；这些也不等价于真实 CVD |
| 全市场广度 | 五币篮子是用户选定的有限范围，不是“全市场” | 明示篮子及覆盖率。以后若需要全市场广度，需另定资产集合和成员历史规则；本轮没有任意扩展 |
| ETH 相对 BTC 缺少对齐基准 | 可由 API 提供，但请求失败、历史不足或时间不齐仍可能发生 | 三项记 MISSING，而非 NOT_APPLICABLE；继续用 ETH 自身已确认结构和其他有效证据。BTC 对自身比较仍正常标不适用 |

公开接口的边界参考 [OKX 强平频道](https://www.okx.com/docs-v5/en/#public-data-websocket-liquidation-orders-channel)、[资金费率历史](https://www.okx.com/docs-v5/en/#public-data-rest-api-get-funding-rate-history)、[主动成交统计](https://www.okx.com/docs-v5/en/#trading-statistics-rest-api-get-contract-taker-volume)。时间戳的区间起点口径来自本轮公开数据交叉核对：最近已结束 1h 主动成交与同起点 K 线成交量一致，5m 汇总也一致；OI/多空比的 1h 桶与其末尾 5m 观测对应。官方字段只写 Timestamp，交叉核对依据和限制另行保留，未声称文档明确承诺所有细节。

## 独立审查与验证

实现后按用户要求启动了独立 Agent，审查逻辑并新增独立单元、真实 PostgreSQL 测试。审查发现两项问题并已修复：

1. 不能把缺期历史费率的记录间隔当真实结算周期来归一化。
2. 恒定复利收益经浮点运算可能出现微小假方差，造成异常巨大的 beta。现在先用 Decimal 计算收益，标准差不超过 1e-12 的收益视为数值退化，不输出相关性或 beta 的假精确结果；相对强弱仍可独立计算。

后续主动成交跨源核对也经过该 Agent 复核并补测：逐根总量一致保持有效；单根不足保留原值并降级；两根偏差互相抵消、总体恰好相等时仍能发现差异。

公开数据采集时间为北京时间 2026-10-31 01:48:50—01:49:02。当前公开数据验证覆盖 BTC、ETH × 1h/4h/6h/12h，共 8 组。完成跨源检查后的同批输入重算结果为：

| 每组输入 | OK | 部分覆盖 | MISSING | 正常不适用 |
| --- | ---: | ---: | ---: | ---: |
| BTC，各 4 个周期 | 31 | 2：CVD、主动买卖比 | 1：强平 | 3：BTC 自身比较 |
| ETH，各 4 个周期 | 34 | 2：CVD、主动买卖比 | 1：强平 | 0 |

这里的强平 MISSING 是公开 GET 专项没有启动采样器，因此没有强平窗口输入；强平接入及计算另外用真实 PostgreSQL 中的样例事件验证。**不能把这 8 组公共数据验证说成线上完整验收，也不能和旧 C 轮 10 份输入直接比较通过率。**

## 技术实现与自主决定

- 外部请求在数据库事务外执行；冻结时，在同一个任务授权、租约、fence、期限校验事务中保存 BTC 基准及强平窗口。重试复用原冻结输入；迟到数据不改写旧输入/hash、预测或评分。
- 单个子预测只采一个周期，避免每个子任务重复拉四周期；外部可选数据共享预算由 5 秒调整为 20 秒，仍受原有总采集截止时间约束，复用现有 HTTP 限速与连接池。没有增加独立行情服务或新网关。
- 三种统计采用 open 时间口径；未完成桶剔除。主动成交 API 数组顺序为卖量、买量，明确请求币数量单位。只在逐桶能与计算 K 线对应时做成交量核对，相对容差 1e-6，并保留绝对容差 1e-8；细粒度或多桶汇总来源保留原有覆盖检查，不谎称完成同一核对。
- 核心 OHLCV 公式及必要指标四项保持；37 个指标名称保持。新增资金费率历史摘要和证据政策是上下文，不额外包装成“已验证的新交易信号”。
- 用户要求相关性为弱证据，本轮将同一 BTC 基准派生的 beta、相对强弱也一起限制为弱证据，防止换一个名称就把同一信息升级。约束落实到明确标签、数据说明及子/父/复盘提示词；不虚称已证明真实模型永远不会在文字里过度解释。
- 外部观测契约版本更新，默认配置指向新特征版本与已确认篮子。旧部署配置不会因本地修改自动生效，后续部署需更新对应配置、匹配引擎和提示词锁；不能直接使用此前生成的旧部署包。

本轮主要涉及采集、量化、强平采样、预测冻结、模型输入、配置与六角色提示词，以及相应测试。没有数据库迁移。完整本轮前副本、公开只读原料与测试日志位于忽略目录 `.local/private-evidence`。旧审计结论保留在 [原缺失诊断](indicator-unavailable-diagnosis-2026-10-30.md)，不倒填为当时已修复。
